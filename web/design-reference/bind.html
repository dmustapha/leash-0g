Bind an external agent · guided

Your agent already runs somewhere else. Binding it to LEASH means one change only — its base_url swaps to the gateway below. You don't rewrite the agent. LEASH then sees every inference and tool call, and you can govern, approve, and revoke it.

2 · Name & scope

name · required
A label for this bound agent. Shown across the console and revoke list.
tool allowlist · optional, default-deny
Starts empty · no tools until you add them. Default-deny — the agent can't call a tool you didn't grant.
LeashAccount · optional — most binds have none
If you already hold an on-chain LeashAccount, reference it to tie spend limits on-chain. Optional — observe-mode binds usually skip it.

3 · Interaction mode the key decision

How deeply LEASH acts on the agent. Only observe is live in SF-2 — it needs no change to your agent beyond the base_url swap. The other two are declared, not yet live: each carries a cost that would break no-rewrite, so they're deferred.

4 · Where to paste it per-platform · partial coverage

Paste the gateway URL + token into your platform's custom OpenAI-compatible endpoint field. Coverage is platform-dependent — these are representative stubs, not every platform.

OpenAI-compatible base_url Generic · works anywhere
Set base_url → the gateway URL, and api_key → your gateway token. Any client that lets you override both will route through LEASH.
Flowise / LangFlow Field: Base Path
In the ChatOpenAI node → BasePath = gateway URL, OpenAI API Key = gateway token.
Custom GPT platforms (self-host) Field: API Base URL
Under model settings → API Base URL = gateway URL, API Key = gateway token. Supported only where the platform exposes both fields.
Chat-only tools — claude.ai, ChatGPT app Not bindable
These don't let you set a base_url — there's nothing to redirect. A hosted chat UI can't be bound; bind the agent that calls the model, not the chat window.

Tool allowlist · reuses SF-3's editor

A bound agent's tools are governed by the same editor native agents use — nothing new to learn. LEASH doesn't rebuild the allowlist per bind type; a bound agent is just an agent to the policy layer.

Same governed tool-use editor. Grant allowed per tool, cap maxArgBytes, scope recipientAllowlist / urlOriginAllowlist, pick a preset — exactly as for native agents.

The default-deny invariant holds here too: a freshly bound agent has zero tools until you grant them, and a sensitive tool always asks at call time even when allowlisted.
